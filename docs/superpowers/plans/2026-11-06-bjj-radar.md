# BJJ Radar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A phone-first web app that tracks elite BJJ events (gi/no-gi), results, and free YouTube full matches, updated weekly by Claude plus an on-demand YouTube refresh.

**Architecture:** A static site (no build step, ES modules) plus one Cloudflare Worker (static assets + `/api/refresh`). Data lives in JSON files in the repo and is rewritten by a weekly Claude scheduled task that commits; Cloudflare Workers Builds redeploys on each commit. Pure logic (matching, spoilers, digest) lives in small modules tested with Node's built-in test runner.

**Tech Stack:** Vanilla HTML/CSS/JS (ES modules), Node 20 `node:test`, Cloudflare Workers + Wrangler, YouTube Data API v3 (`playlistItems.list`), `@resvg/resvg-js` (icon export, dev only).

**Spec:** `docs/superpowers/specs/2026-11-06-bjj-radar-design.md`

## Global Constraints
- Elite events only: IBJJF majors, ADCC Worlds + Trials, WNO, UFC BJJ, CJI, BJJ Stars, Polaris.
- Seed window: last 12 months plus everything scheduled through 2027. About 30 athletes and about 10 teams.
- Whitelisted channels only: FloGrappling, IBJJF, UFC BJJ, CJI, BJJ Stars, Polaris, ADCC, WNO.
- Refresh never calls Claude; Claude runs only weekly (Monday).
- No notifications, no email, no device sync.
- Light background, no grey surfaces; gi = blue, no-gi = orange; color only to aid scanning.
- Spoilers: outcomes are behind a per-item tap, and the reveal is remembered. Winner-revealing titles are shown as "X vs Y". "New" markers never reveal winners.
- Profile links are shown only when `linksVerified` is true.
- The app icon is original, with no logos or likenesses. Chabes picks from 2–3 options.
- Every `localStorage` access is wrapped in try/catch.

## Review Focus
1. Sibling athletes sharing a surname (Kade vs Tye Ruotolo): a surname-only title must yield "maybe", not a confident match to one twin.
2. Recurring event names ("Worlds" every year): a video matches the edition whose date window contains `publishedAt` (event end + 120 days), never a past year's edition.
3. Portuguese/alternate separators ("A x B", "A vs. B", "A VS B") and "LUTA COMPLETA": parsed the same as "vs" and "FULL MATCH".
4. First-ever open (no lastVisit) and absences longer than the data window: home shows the last 30 days instead of crashing or showing everything.
5. Refresh without an API key, or over quota: the function returns `{error}` with status 503/429, and the UI shows the quiet fallback message while keeping Monday's data.
